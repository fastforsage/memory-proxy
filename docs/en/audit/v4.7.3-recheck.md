## 0. Summary

**Noticeable progress.** Of the 17 checked items from the first audit, 12 are fixed, 3 partially, the rest are open (the author moved H-1 and M-5 to v4.8 themselves). Highlights:
- the sources in git are **byte-identical** to the image;
- conversation exfiltration via CORS is closed;
- the cold path became atomic;
- Russian text no longer disables memory.

**But 6 new problems appeared**, two of them regressions caused by the fixes themselves:

| ID | What | Severity |
|---|---|---|
| NEW-1 | CSRF: a POST with `Content-Type: text/plain` from any site runs without a preflight. It can **poison memory** (inject facts and prompt injections) | 🟠 High |
| NEW-2 | The `Host` header is not checked. Through DNS rebinding a page gets same-origin access to the proxy without a key and **reads the answers** | 🟠 High |
| NEW-3 | **Regression:** `/chats`, `/pull`, `/search` do not work at all and always return the help text | 🟡 Medium (feature broken) |
| NEW-4 | **Regression:** the new `preclassify` gives false "technical" on ordinary personal messages. Affected: emotions with `!` and `:)`, lists with `-`, links, **any English text** | 🟠 High (memory silently turns off) |
| NEW-5 | A short code block (< 80 characters) is treated as "personal". Because of this **a test fails and so does the whole CI**; the image was pushed by hand | 🟡 Medium |
| NEW-6 | `hmac.compare_digest` on `str`: a non-ASCII character in `Authorization` gives 500 instead of 401 | 🔵 Low |

**Verdict:** a good iteration, but v4.7.3 was released with a red CI and broken commands. Before v4.8 it is worth releasing **v4.7.4** fixing NEW-1…NEW-6. That is about 40 lines of code; ready patches are in §4.

## 2. New findings

### 🟠 NEW-1. CSRF: poisoning memory from any site
`proxy.py:537-546` (no `Content-Type` or `Origin` check)

Without the CORS middleware the browser does not let a foreign page **read** the answer, but it can **send** a "simple" request (`Content-Type: text/plain`, no preflight). Starlette's `request.json()` parses the body regardless of `Content-Type`, so the request runs fully:
- the message is stored in `messages` and later shows up in the Context Bridge of other chats (prompt injection);
- cold analysis runs and facts favourable to the attacker are written to memory;
- GPU time is spent (generation).

**PoC:** `POST text/plain` with `Origin: https://evil.example` returned 200, 2 messages were stored, and `works_at: EvilCorp` appeared in `facts`.

### 🟠 NEW-2. DNS rebinding: Host is not checked
Without a key the service answers any `Host`. After rebinding, the attacker's domain points to 127.0.0.1 and the page becomes same-origin with the proxy. Then it can:
- read `/v1/models`;
- send chat requests like "what do you know about me?" and **read the model's answer**, which has facts from memory mixed in;
- once NEW-3 is fixed, read `/pull` and `/chats` directly.

This is a classic class of attacks on local LLM services (Ollama was attacked this way). Newer browsers partly protect against it through Local Network Access, but not all of them and not always.

**PoC:** `Host: attacker-rebind.example:8081` → 200 on both `/v1/models` and `/v1/chat/completions`.

### 🟡 NEW-3. Regression: slash commands do not work
`proxy.py:39`, `587-594`
```python
COMMAND_RE = re.compile(r"^/(chats|pull|search|help)…")   # group 1 = "chats", without the slash
cmd = cmd_match.group(1).lower()                         # "chats"
if cmd == "/chats": …                                    # never True
else: resp_text = "/chats, /pull <N>, /search <query>"   # always the help text
```
**PoC:** the answer to `/chats` is `'/chats, /pull <N>, /search <query>'`.

The test `test_command_regex` checks only `match()`, not the dispatch. The lesson: integration tests through `TestClient` are needed.

### 🟠 NEW-4. Regression: false "technical" in the new preclassify
`proxy.py:62-71`

| Message (personal) | Why it became `technical` |
|---|---|
| «Привет!!! Сегодня отличный день :) … в 10:30 … (наконец-то)» ("Hi!!! Great day today :) … at 10:30 … (finally)") | the share of `!:()-` = 8.4% against a 4% threshold |
| «Планы на неделю:\n- купить продукты\n- позвонить маме…» ("Plans for the week:\n- buy groceries\n- call mum…") | list markers `-` and `:` = 4.5% |
| «Посмотри квартиру: https://www.avito.ru/…» ("Look at this flat: https://www.avito.ru/…") | `:/-._` in the URL = 6.8% |
| "I work **for** a startup **from** Berlin and **if** … **for** … **while** …" | `CODE_KEYWORDS` is case-sensitive and contains ordinary English words `for/from/if/while/else/try/let/var` |

For all such messages memory is **not added** and facts are **not extracted**. The user will not notice this in any way. The root cause: the set of "code" characters includes `! : - ( ) / + *`, which are common in ordinary speech.

### 🟡 NEW-5. Short code and a red CI
The check `if len(text) < 80: return "personal"` comes **before** the ```` ``` ```` check. So ```` ```python\nprint(1)\n``` ```` (25 characters) gets `personal`, and `tests/test_proxy.py::test_preclassify_code` fails. Reproduced locally with the same package set that CI installs: `1 failed, 9 passed`. Because of this the workflow never reaches the build, and the v4.7.3 image was pushed by hand.

### 🔵 NEW-6. Non-ASCII in Authorization → 500
`hmac.compare_digest(str, str)` raises `TypeError: comparing strings with non-ASCII characters is not supported`. The service returns 500 instead of 401 (PoC in `auth` mode). This does not harm security, but it pollutes the logs and reveals that the check exists.

### 🔵 Repository hygiene
- **The README was cut to 8 lines** and went stale immediately. The item "Replace `ВАШ_НИК` (YOUR_NICK) in docker-compose.yml" refers to something that is not in compose. `API_KEY`, `CORS_ORIGINS`, `EXTRACT_URL/MODEL`, `GLOBAL_MEMORY`, `ENABLE_FORWARD_USER_INFO_HEADERS`, the vector migration (`cleanup_vec.py`) and slash commands are not described. The false promises are gone, which is good, but now there is simply no documentation.
- **`build.log` from v4.6** is committed to the repo. It has a different Dockerfile and `transformers==4.57.1`, while `requirements.txt` pins 4.46.3. This is misleading; the file is better deleted.
- `check_db.py` hardcodes the path `/home/admin/memory-mvp/data/memory.db`. `cleanup_vec.py` uses `/data/memory.db`, and the script **deletes all vectors without confirmation**.
- CI installs **unpinned** packages (`pip install fastapi httpx …`) rather than `-r requirements.txt`. Tests run on different versions than the image.
- CI pushes `latest` on every commit to `main`, not only on a release tag.
- `.gitignore` has duplicate entries.
- Dependencies were not updated (the OSV table from the first audit still applies). The newly added `anyio==4.4.0` has 2 advisories, but it is unused.

## 4. Patch for v4.7.4 (≈40 lines)

### NEW-1 and NEW-2: CSRF and DNS rebinding
```python
from starlette.middleware.trustedhost import TrustedHostMiddleware

ALLOWED_HOSTS = [h.strip() for h in os.getenv(
    "ALLOWED_HOSTS", "localhost,127.0.0.1,host.docker.internal,memory-proxy").split(",") if h.strip()]
app.add_middleware(TrustedHostMiddleware, allowed_hosts=ALLOWED_HOSTS)   # NEW-2

def reject_cross_site(request: Request):                                   # NEW-1
    ct = request.headers.get("content-type", "").split(";")[0].strip().lower()
    if ct != "application/json":
        raise HTTPException(415, "Content-Type must be application/json")   # forces the browser into a preflight
    if request.headers.get("sec-fetch-site") == "cross-site":
        origin = request.headers.get("origin", "")
        if origin not in _origins_list:                                     # the list from CORS_ORIGINS
            raise HTTPException(403, "cross-site request blocked")

@app.post("/v1/chat/completions")
async def chat(request: Request):
    check_auth(request)
    reject_cross_site(request)
    ...
```
Server-side clients (Open WebUI, SillyTavern, curl) always send `application/json` and do not send `Sec-Fetch-Site`, so they are not affected.

### NEW-3: commands
The minimal fix is one line:
```python
cmd = "/" + cmd_match.group(1).lower()
```
Better to catch only exact commands right away (verified: `/chats`, `/help`, `/pull 2` and `/search jwt auth` are recognised; "/help me write…", "/chats are great", `/etc/...` and a bare `/pull` go to the LLM):
```python
COMMAND_RE = re.compile(r"^/(?:(chats|help)\s*|(pull|search)\s+(.+))$", re.I | re.S)
...
cmd = "/" + (cmd_match.group(1) or cmd_match.group(2)).lower()
arg = (cmd_match.group(3) or "").strip()
```

### NEW-4 and NEW-5: preclassify
A variant tested on 12 examples (all pass, including the repo's tests); it is in `preclassify_suggestion.py` (went into v4.7.4):
```python
CODE_LINE = re.compile(
    r"^\s*(?:def |class |import |from \S+ import |return\b|#include|public |private |"
    r"function\b|const |let |var |if\s*\(|for\s*\(|while\s*\(|"
    r"(?:SELECT|INSERT|UPDATE|DELETE|CREATE|ALTER)\s|"      # SQL, upper case only
    r"[{}\]]\s*[;,]?\s*$|"                                 # a line with a single bracket
    r"[\w.]+\s*\(.*\)\s*[;{:]?\s*$|"                       # a function call taking the whole line
    r"[\w.\[\]'\"]+\s*[+\-*/]?=\s*\S)", re.M)              # an assignment
STRONG = set("{};=<>[]")                                   # without ! : - ( ) /, which are common in speech

def preclassify(text: str) -> str:
    if "```" in text: return "technical"                   # before the length check (NEW-5)
    lines = [l for l in text.splitlines() if l.strip()]
    code_lines = len(CODE_LINE.findall(text))
    if code_lines >= 3 or (len(lines) >= 2 and code_lines / len(lines) >= 0.5): return "technical"
    if len(text) < 80: return "personal"
    if len(lines) == 1 and code_lines == 1: return "technical"
    if sum(c in STRONG for c in text) / len(text) > 0.03: return "technical"
    return "personal"
```
| Example | Result |
|---|---|
| A Russian story, emotions with `!!! :)`, a to-do list, personal English text, an avito link, «Update: мы переехали…» ("Update: we moved…") | `personal` ✅ |
| ```` ```python print(1)``` ````, Python (×2), one-line SQL, JSON, 4 lines of JS | `technical` ✅ |

### Vector migration (M-3)
Today, when upgrading from v4.7.2, the old vectors (without a prefix) stay and are compared with prefixed queries. The solution is to version the schema:
```python
EMB_VERSION = 2   # 2 = USER2 with prefixes
if _conn.execute("PRAGMA user_version").fetchone()[0] < EMB_VERSION:
    with _conn: _conn.execute("DELETE FROM vec_facts")
    _conn.execute(f"PRAGMA user_version={EMB_VERSION}")
backfill_vec()    # re-embeds all current facts
```
