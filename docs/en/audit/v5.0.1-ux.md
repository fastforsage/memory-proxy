# UX tests v5.0.0 → v5.0.1

[Русский](../../audit/v5.0.1-ux.md) | **English**

> English translation of [`docs/audit/v5.0.1-ux.md`](../../audit/v5.0.1-ux.md). If the two differ, the Russian original is authoritative.

What a person who installs memory-proxy and uses it every day sees: connecting a client, errors, memory, commands, client service requests, regenerate, model crashes, `manage.py`. Everything found is fixed in v5.0.1.

## How it was tested

- **Backend:** llama.cpp `llama-server` b12812, `-c 4096 -np 1 -t 2 --jinja`. Models: Qwen2.5-0.5B-Instruct Q4 (main run) and Qwen2.5-1.5B-Instruct Q4 (fact extraction check). Machine: 2 CPUs, 2 GB RAM, no GPU.
- **Proxy:** from source, `API_KEY=sk-test`, the default USER2-small embedding model.
- **Clients:** a probe script on `httpx` and the official OpenAI SDK. It reproduces the requests of Open WebUI (service templates taken from the Open WebUI main sources: title, tags, follow-ups, search query, autocomplete, emoji, MoA, tool selection), SillyTavern (system + examples + names, the service summary), an agent with `tools` (Cline/Continue) and a message with an image.
- **Failures:** backend stopped; a fake backend that breaks the stream after two chunks and returns truncated JSON without streaming.
- **Scenarios:** first connection, plain chat, SDK, "told about myself → remembered in a new chat → forgotten", the real Open WebUI flow (answer → title/tags/follow-ups → `/facts` → next question), all slash commands, continuing after a command, errors, regenerate and edit, SillyTavern, agent, image, `manage.py`, backend unreachable.

## Findings

| # | What the user saw | Cause | Fix |
|---|---|---|---|
| B1 | Wrong key, broken JSON, malformed `messages` → `{"detail": "…"}`; the OpenAI SDK and clients show "Unknown error" | FastAPI default responses | All errors are `{"error": {"message", "type", "code"}}`; `detail` is kept for compatibility |
| B2 | Opened the proxy by a LAN IP → `Invalid host header`, no idea what to do | `TrustedHostMiddleware` | A JSON error with a hint about `ALLOWED_HOSTS`; the log says which name to add |
| B3 | POST without `Content-Type: application/json` → an unclear error | — | 415 in OpenAI format |
| B7 | Message too long → 400 without the limit | — | 413, the text has the length and `MAX_INPUT_LEN` |
| — | Model not running → 500 and a traceback in the proxy log, "Internal Server Error" in the client | An `httpx` exception was not handled | 502 `backend_unavailable` / 504 `backend_timeout` with the address and a hint about `LLAMA_URL`; the same for `/v1/models` |
| B4 | `/fact` (no s) went to the model, which answered something of its own | — | "❓ Команды /fact нет. Возможно, /facts?" (difflib, cutoff 0.75; with arguments 0.85). Exact commands with text (`/help me write…`) and foreign ones (`/imagine`, `/etc/hosts`) still go to the model |
| **B5** | **Told about myself — `/facts` is empty. In Open WebUI facts were never stored** | (a) After every answer Open WebUI sends 2–3 service requests; each preempted the background extraction, which gave up after 4 attempts. (b) A schema prompt with placeholders and a comma-separated list: Qwen 0.5B/1.5B returned the placeholders, invented predicates and paraphrased quotes, and validation dropped everything. (c) If the model called the message "technical", personal facts were lost too | (a) Retry for up to `COLD_RETRY_S` (30 min); commands do not touch the background. (b) A new prompt: predicates with descriptions, rules, an example; predicate synonyms; fuzzy quote matching; rejection counters in the log. (c) First-person facts are kept in that case. A/B on Qwen2.5-1.5B, 10 typical messages: **1 → 15** correct facts |
| B6 | Open WebUI "pick an emoji", MoA and tool-selection requests were stored in history and sent to fact extraction | Not in the list of service templates | Added; the system prompt of a single-message request is checked too (`SERVICE_SYSTEM_PATTERNS`) |
| B8 | Regenerate → two answers to one question in history, the rejected one among style examples | The new answer was appended | It replaces the previous answer; the previous style example is removed |
| B9 | The backend crashed mid-answer → the stream just stopped (curl rc=18), the client did not know the answer was incomplete; the fragment was saved as the answer | An exception in the stream generator | An SSE `error` event (`backend_stream_error`) and `[DONE]`; the fragment is not saved |

### Found while re-checking the fixes

| # | What | Fix |
|---|---|---|
| R1 | **Style example loop.** 0.5B once answered "As an artificial intelligence, I cannot…", the answer became a style example, the model started copying it for any question, and every copy became an example again | An answer that repeats an example verbatim removes the example and is not saved itself; an answer truncated by `max_tokens` (`finish_reason=length`) does not become an example |
| R2 | Junk facts `has_pet: любил`, `likes: любил` from the quote "любимый цвет" ("favourite colour") | The value must match a word of the quote up to its ending, not just by prefix: "Казань" ↔ "Казани" yes, "любил" ↔ "любимый" no |
| R3 | `name: Маша` from "went out with my wife Masha"; `works_at: Google` from "Google didn't hire me" | `name` only for a self-introduction; negated facts are rejected (except `dislikes`) |
| R4 | The backend answered 200 with truncated JSON → the proxy passed broken JSON to the client | 502 `backend_bad_response` |
| R5 | If a client disconnected mid-stream, `await aclose()` could raise `CancelledError` before the "user request in progress" mark was cleared, so the background would wait forever | The mark is cleared before the `await`; `/health` shows `background.waiting_for_user_requests` |
| R6 | An intermediate version of the B5 fix did not let service requests preempt the background, so the chat title waited up to 3 minutes behind fact extraction | Service requests preempt the background again; the extraction is not lost thanks to the retry (a) |
| R7 | `GET /` → 404; `/health` did not say whether the model is alive | `GET /` describes the service; `/health.backend.reachable` |

### Not fixed

- **Image without mmproj.** llama.cpp answers 500 "image input is not supported… provide the mmproj"; the proxy passes it through as is, and the text is clear.
- **Roleplay.** Facts about the user's character in SillyTavern ("I'm Igor, a blacksmith from the village") are stored as facts about the user. Separating the character from the person is a separate task.
- **Open WebUI voice templates** (voice assistant, TTS renderer) are not in the service list and were not tested. If they reach memory, add a marker via `SERVICE_PATTERNS` / `SERVICE_SYSTEM_PATTERNS`.
- **0.5B answer quality.** The model sometimes answers in English or ignores the memory; that is the model, the proxy gives it the memory correctly (checked by capturing the request to the backend).

## Notes on the run

- On 2 GB RAM, Qwen2.5-1.5B together with two proxy instances pushes the model weights out of the page cache: generation drops from ~10 to 1 token/s and background extraction takes minutes. With one proxy or with 0.5B it is normal (~25 tokens/s). This is a limit of the test box, not of the proxy, but keep in mind that the proxy with its embedding model takes ~300 MB.
- The probe is `ux_probe.py` (outside the repository): scenarios `onboarding basic sdk memory owui commands continuity tasks errors regen st agent vision cli` and `down=<url>`.
