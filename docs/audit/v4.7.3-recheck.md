## 2. Новые находки

### 🟠 NEW-1. CSRF: отравление памяти с любого сайта
`proxy.py:537-546` (нет проверки `Content-Type` и `Origin`)

Без CORS-middleware браузер не даёт чужой странице **прочитать** ответ, но **отправить** «простой» запрос (`Content-Type: text/plain`, без preflight) может. Starlette `request.json()` разбирает тело, не глядя на `Content-Type`, так что запрос полностью выполняется:
- сообщение сохраняется в `messages` и потом попадает в Context Bridge других чатов (prompt-инъекция);
- запускается cold-анализ, и в память пишутся факты, выгодные атакующему;
- тратится GPU (генерация).

**PoC:** `POST text/plain` с `Origin: https://evil.example` вернул 200, сохранено 2 сообщения, в `facts` появился `works_at: EvilCorp`.

### 🟠 NEW-2. DNS rebinding: Host не проверяется
Сервис без ключа отвечает на любой `Host`. Атакующий домен после rebinding указывает на 127.0.0.1, и страница становится same-origin с прокси. Тогда она может:
- читать `/v1/models`;
- слать чат-запросы вроде «что ты знаешь обо мне?» и **читать ответ модели**, в который подмешаны факты из памяти;
- после починки NEW-3 — читать `/pull` и `/chats` напрямую.

Это классический класс атак на локальные LLM-сервисы (так атаковали Ollama). Новые браузеры частично защищают от него через Local Network Access, но не все и не всегда.

**PoC:** `Host: attacker-rebind.example:8081` → 200 и на `/v1/models`, и на `/v1/chat/completions`.

### 🟡 NEW-3. Регрессия: слэш-команды не работают
`proxy.py:39`, `587-594`
```python

### 🟠 NEW-4. Регрессия: ложные «technical» в новом preclassify
`proxy.py:62-71`

| Сообщение (личное) | Почему стало `technical` |
|---|---|
| «Привет!!! Сегодня отличный день :) … в 10:30 … (наконец-то)» | доля `!:()-` = 8,4 % при пороге 4 % |
| «Планы на неделю:\n- купить продукты\n- позвонить маме…» | маркеры списка `-` и `:` = 4,5 % |
| «Посмотри квартиру: https://www.avito.ru/…» | в URL `:/-._` = 6,8 % |
| «I work **for** a startup **from** Berlin and **if** … **for** … **while** …» | `CODE_KEYWORDS` чувствителен к регистру и содержит обычные английские слова `for/from/if/while/else/try/let/var` |

Для всех таких сообщений память **не подставляется** и факты **не извлекаются**. Пользователь этого никак не заметит. Корень проблемы: в набор «кодовых» символов попали `! : - ( ) / + *`, а они постоянно встречаются в обычной речи.

### 🟡 NEW-5. Короткий код и красный CI
Проверка `if len(text) < 80: return "personal"` стоит **раньше** проверки на ```` ``` ````. Поэтому ```` ```python\nprint(1)\n``` ```` (25 символов) получает `personal`, и `tests/test_proxy.py::test_preclassify_code` падает. ### NEW-4 и NEW-5: preclassify
Вариант, проверенный на 12 примерах (все проходят, включая тесты репозитория); лежит в `preclassify_suggestion.py` (вошёл в v4.7.4):
```python
CODE_LINE = re.compile(
    r"^\s*(?:def |class |import |from \S+ import |return\b|#include|public |private |"
    r"function\b|const |let |var |if\s*\(|for\s*\(|while\s*\(|"
    r"(?:SELECT|INSERT|UPDATE|DELETE|CREATE|ALTER)\s|"      # SQL — только в верхнем регистре
    r"[{}\]]\s*[;,]?\s*$|"                                 # строка из одной скобки
    r"[\w.]+\s*\(.*\)\s*[;{:]?\s*$|"                       # вызов функции на всю строку
    r"[\w.\[\]'\"]+\s*[+\-*/]?=\s*\S)", re.M)              # присваивание
STRONG = set("{};=<>[]")                                   # без ! : - ( ) / — они частые в речи

def preclassify(text: str) -> str:
    if "```" in text: return "technical"                   # раньше проверки длины (NEW-5)
    lines = [l for l in text.splitlines() if l.strip()]
    code_lines = len(CODE_LINE.findall(text))
    if code_lines >= 3 or (len(lines) >= 2 and code_lines / len(lines) >= 0.5): return "technical"
    if len(text) < 80: return "personal"
    if len(lines) == 1 and code_lines == 1: return "technical"
    if sum(c in STRONG for c in text) / len(text) > 0.03: return "technical"
    return "personal"
```

| ```` ```python print(1)``` ````, Python (×2), однострочный SQL, JSON, JS из 4 строк | `technical` ✅ |

### Миграция векторов (M-3)
Сейчас при обновлении с v4.7.2 старые векторы (без префикса) остаются и сравниваются с запросами с префиксом. Решение — версионировать схему:
```python
EMB_VERSION = 2   # 2 = USER2 c префиксами
if _conn.execute("PRAGMA user_version").fetchone()[0] < EMB_VERSION:
    with _conn: _conn.execute("DELETE FROM vec_facts")
    _conn.execute(f"PRAGMA user_version={EMB_VERSION}")
backfill_vec()    # переэмбеддит все актуальные факты
```
